# Support

## Data correction

If a status code, phrase, provider, lifecycle state, source, or description looks wrong, open a **Data / source correction** issue and include the strongest primary source you can find.

## Bug

For CLI, Web UI, API, build, or validation bugs, use the **Bug report** issue template and include reproduction steps.

## Feature idea

Use the **Feature request** template for new providers, exports, integrations, developer tooling, or usability improvements.

## Security

Do not post sensitive vulnerability details in a public issue. Follow [`SECURITY.md`](SECURITY.md).

## Before opening an issue

Please search existing issues first. Clear, reproducible reports with links to authoritative documentation are the easiest to act on.
