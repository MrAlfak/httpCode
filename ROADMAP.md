# Roadmap

httpCode aims to become a practical, source-aware HTTP status reference that is useful as a dataset, CLI, API, and web explorer.

## Near term

- Expand verified vendor coverage from primary documentation.
- Improve translation coverage and review status.
- Add richer examples for real API responses and debugging scenarios.
- Add more dataset integrity tests and source freshness checks.
- Improve accessibility, keyboard navigation, and mobile UX.
- Publish a live static explorer through GitHub Pages.
- Improve package metadata and distribution workflows.

## Next

- OpenAPI description for the read-only API.
- Typed JavaScript / TypeScript data package.
- Python package publishing workflow.
- Machine-readable source provenance history.
- Provider-specific changelog / lifecycle tracking.
- Search aliases for common developer terminology.
- Better SEO landing pages for individual status codes.
- Optional compact dataset builds for embedded tooling.

## Contribution-friendly ideas

Good first contributions include:

- verifying one vendor code against primary documentation;
- translating missing status descriptions;
- adding tests for an edge case;
- improving one documentation example;
- accessibility fixes;
- adding a provider filter or search alias.

Open a feature request if you want to take ownership of an item.
